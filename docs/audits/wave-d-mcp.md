## Implementation and validation record — 2026-09-27

The audit led to an additive host-installed controlled mode in the existing Node
STDIO bridge, a closed 4096-byte handoff schema and a real embedding under
`examples/controlled-ability`. The application and Dispatch stay Kujo-native.
No producer-selected module/path or verifier is loaded. Existing standalone tests
remain unchanged. The published Ability profile's `sdk` application surface stays
unchanged: MCP is the outer transport, not a new application profile.

Fresh review found that `readline` assembled an unbounded incomplete request before
checking its length. Controlled mode now uses bounded raw UTF-8 framing (8192 bytes),
rejects malformed UTF-8 and caps inflight requests at eight. Standalone framing is
unchanged. New subprocess tests cover unterminated oversize input and malformed
requests before any application invocation.

Local validation: controlled unit/subprocess tests, existing standalone host bridge,
full `KUJO_BIN=/tmp/kujo-wave-a-release-candidate-bin bash tests/run_all_tests.sh`
pass. Existing host certification was regenerated by its actual checks at code
revision f226601be08a48e7b9083f0cd3c6b42c1e43aac2, then the generated compatibility
matrix and fail-closed freshness tests pass. The first certification attempt lacked
installed Ability Gateway test dependencies; isolated Workers test reproduced the
module-resolution failure. Installing its existing lockfile dependencies with
`npm ci` resolved it; the real certification rerun passed without source changes or
suppressed checks. Historical managed-read evidence remains historical; no new
remote authentication claim is made.

Dispatch's two real fixtures pass business-commit/receipt-failure and actual server
exit-before-reply, each with 21 correlation/integrity negatives, expired/stale and
duplicate ticket denial, locked replay rejection, fresh-controller continuation and
standalone replay. Each leaves one business effect and one final receipt. The full
cross-repository record is Dispatch `docs/audits/wave-d-mcp.md`; machine evidence is
under Dispatch `docs/evidence/wave-d-mcp/`. Watchdog is observational, with unknown
usage preserved as null. MCP does not verify assurance or decide replay.
